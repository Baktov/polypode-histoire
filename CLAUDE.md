# CLAUDE.md — Polypode Histoire (Addon WoW)

Conventions communes et procédure de documentation de tous les modules Polypode (chargées
automatiquement, quel que soit le dossier ouvert) :

@../Polypode/MODULES.md

Addon compagnon de **Polypode** (dossier voisin `../Polypode`, dépôt séparé) : **journal
chronologique commun** des événements importants de tous les personnages joués. Rester **simple** :
on n'ajoute un type d'événement que s'il raconte l'histoire des personnages, sans détail superflu.

## Architecture

|---|---|
| `Locale.lua` | Chargé en premier : table de textes `ns.L = P.NewLocale()` (repli : table qui renvoie la clé française avec un Polypode trop ancien) et `ns.OnLanguageApplied(fn)` (→ `P.OnLanguageApplied`, sinon appel immédiat) pour les textes rangés au chargement (bouton de barre de titre, aide de commande, nom pour `P.RegisterCharacterData`...). | Textes du journal (Histoire.lua, `EventText`) | Deux formats par événement, singulier et pluriel, `say(L["%s atteint..."], L["%s atteignent..."], ...)` (premier `%s` = noms) ; guillemets `L["« %s »"]` ; mois `MONTHS` (en tête), `MONTHS_IN_TEXT` (dans une phrase : minuscule en français, pas en anglais ni en allemand), `WEEKDAYS` ; dates par formats traduits (`L["%d/%m/%Y"]`...) ; Frise.lua : mois et jours abrégés en une clé chacun, découpée par `strsplit` (« mars » abrégé = « mars » entier en français) |

Contrôle : `python Polypode\tools\check_locale.py Polypode_Histoire` |
| `Polypode_Histoire.toc` | `## Dependencies: Polypode`, SavedVariables par personnage `PolypodeHistoireChar` (`rep[factionID]` = rang connu ; `friends`, `bnet` = `{ [nom] = true }`, `guild` = nom ou "", `clubs` = `{ [id] = { name, b } }` ; écrit par le seul client du personnage), de compte `PolypodeHistoireData` (le journal ; `guilds[clé]` = guilde actuelle de chaque personnage `{ name, realm }` ou "", 1.18.0, écrit par `CheckSocial` ; `ReadGuild` renvoie nom et royaume — 4e retour de `GetGuildInfo`, sinon `GetRealmName` — ; lu par le site Histoire) et `PolypodeHistoireDB` (fenêtre : `open` repli, `showPatches` case « Ext » (nil = vrai), `view` = "liste" / "frise", `filters` = `{ [catégorie] = true }`, `width` / `height`) |
| `Journal.lua` | Relevé, stockage, synchro, export. Clé du personnage (1.16.1) : `ns.CharKey()` = « Prénom Nom » sur WoW Forever (`P.HasSurnames`, nom de famille de `P.UnitNameParts`, toujours avec une espace ; le royaume de `GetRealmName` y est celui de la couche et change), sinon `P.GetCharKey()` ; `IsMine` accepte les deux formes ; `ns.RosterEntry(clé)` (roster par clé, ou par prénom et nom de famille) ; `ns.Identity(clé)` = « Prénom Nom » pour toute clé dont le roster connaît le nom de famille (regroupement : `SessionDurations`, `DayLines`, pistes de la frise ; `CharName` passe par `RosterEntry`) ; événement reçu accepté par `FromItsCharacter` (clé « Prénom Nom » : `P.FullName` de l'expéditeur, sinon `P.IsSender`). Types : `in` (`PLAYER_ENTERING_WORLD` isLogin → `OnLogin` : si le dernier événement du personnage est un `out` de moins de `SHORT_DELAY` = 180 s, ce `out` est retiré et rien n'est noté ; sinon `loginEvent` / `loginTime`), `out` (`OnLogout` depuis les accroches `Logout` / `Quit` / `ForceQuit`, sinon à `PLAYER_LOGOUT` hors `/reload` — accroches `ReloadUI` / `C_UI.Reload` ; si `loginEvent` date de moins de `SHORT_DELAY`, il est retiré et rien n'est noté, `loggedOut = "short"` ; `CancelLogout` retire le `out` ou remet la connexion). ## Pistes

- Détail dépliable d'un événement (butin d'un gouffre ou d'un donjon) : à vérifier d'abord, les
  messages de butin pouvant être des valeurs secrètes en instance sur Midnight.

## Après chaque modification

Appliquer la procédure de `../Polypode/MODULES.md` (« Après chaque modification d'un module »),
sans attendre qu'on le demande : version du `.toc` et du commit, ligne en tête de la section
« Version » du `README.md` et sections d'utilisation, ce fichier (architecture, dépendances),
Polypode si le périmètre change, puis commit et push sur `origin` (https://github.com/Baktov/polypode-histoire).
